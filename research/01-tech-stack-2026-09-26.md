# Research: tech stack for facemaker (local-only kids face filter + voice changer PWA)

Date: 2026-09-26. Method: /deepresearch, 5 angle agents + 1 claim verifier. Targets: Android Chrome, desktop Chrome/Edge. iOS out of scope. Runtime must make no network calls.

## TL;DR

Stack is browser-native. Face tracking: `@mediapipe/tasks-vision` FaceLandmarker (478 landmarks, 52 blendshapes, transform matrix, one float16 `.task` file, self-hosted). Render: WebGL via Three.js BufferGeometry with fixed index and UVs, per-frame vertex writes. Record: `canvas.captureStream()` + Web Audio `MediaStreamDestination` into `MediaRecorder`. Chrome 126+ writes MP4 H.264/AAC on desktop and Android, WebM is the fallback. Share: `navigator.share({files})` from a button tap. Voice: SoundTouchJS scoped packages (MPL-2.0, AudioWorklet, formant worklet) or Tone.js PitchShift (MIT, delay-line) plus native nodes for robot, echo, telephone. Storage: OPFS for videos, IndexedDB for metadata. Build: Vite + vite-plugin-pwa with `base: '/<repo>/'`, GitHub Actions to Pages. One blocker: tasks-vision 1.0.x sends telemetry to Google. Pin 0.10.35 or block with a meta CSP `connect-src 'self'`.

## Key findings

### Face tracking and render

- **[high]** `@mediapipe/tasks-vision` FaceLandmarker outputs 478 3D landmarks, 52 blendshape scores, and a facial transformation matrix. One float16 `.task` bundle (BlazeFace 192x192, FaceMesh-V2 256x256, blendshape model). IMAGE and VIDEO modes, so one library covers the live face and the static target image. [1, 2]
- **[high]** `detect()` and `detectForVideo()` block the main thread. Docs say use a Web Worker. No official worker example exists, the docs code runs on main thread. Community pattern: transfer `ImageBitmap` frames to a worker and call `close()` on each frame to avoid GPU memory leaks. [2, 6, V8]
- **[high] BLOCKER** `@mediapipe/tasks-vision` 1.0.x contains a metrics logger that POSTs protobuf to `https://odml.pa.googleapis.com/v1/log` every 60 s after task creation. The 1.0.1 README has a Privacy Notice (2026-06-05) and asks integrators to obtain consent. A maintainer said no opt-out is planned. Version 0.10.35 has no such endpoint string. Options: pin 0.10.35, or ship a meta CSP with `connect-src 'self'` and confirm detection still runs when the send fails (the logger sets an error flag and stops). For a children's app the consent requirement matters on its own. [5, V10]
- **[high]** Triangulation index for the 468-point mesh: tfjs-models `demos/shared/triangulation.js`, 2,640 indices, 880 triangles, Apache 2.0. Google's `canonical_face_model.obj` has 468 vertices, 468 UVs, 898 faces, and its face lines index UVs separately from vertices. UVs need remapping to vertex order before use with the 880-triangle index. Landmarks 469 to 478 are iris points, outside the canonical topology. [4, V9]
- **[medium]** Render path: Three.js `BufferGeometry` with a fixed index buffer and fixed UVs, per-frame writes of 468 XYZ positions (`DynamicDrawUsage`, `needsUpdate`). Covers masks, textures, and face-onto-static-image (texture = live video, geometry = target-image landmarks). 2D warps (bulge, big eyes) are a fragment shader over the video texture with landmark uniforms. No fetched source measured fps on mid-range Android. [4]
- **[medium]** Self-host: copy `node_modules/@mediapipe/tasks-vision/wasm` into `public/` and pass that path to `FilesetResolver.forVisionTasks()`. Model `.task` in `public/`, path in `modelAssetPath`. One project reports about 29 MB for the SIMD wasm runtime plus two `.task` models (face and holistic). Face-only size not measured. [2, 6]
- **[medium]** Landmark smoothing applies only when `numFaces` is 1. [1]
- **[low]** TF.js `face-landmarks-detection` wraps the same model and its sample config loads the frozen legacy `@mediapipe/face_mesh` from jsDelivr. Extra layer, no benefit. Skip. [3]
- **[low]** OpenMakeupSDK (MediaPipe + WebGL/Three.js GLSL, face reshaping) is a candidate reference for warp shaders. Not fetched. [8]

### Recording and share

- **[high]** Chrome 126 enabled MP4 container output (H.264 + AAC) in MediaRecorder by default on desktop, Android, and WebView. [16, V1]
- **[high]** Pipeline: `canvas.captureStream(fps)` gives the video track. `AudioContext.createMediaStreamDestination().stream` gives the processed audio track. Combine into one `MediaStream`, pass to `MediaRecorder`. Chrome picks a hardware encoder when `mimeType` is omitted. [10, 13, 14]
- **[medium]** MP4 availability depends on an H.264 encoder on the device. Android has no software H.264 encoder (hardware only). Branded Chrome desktop ships H.264. Feature-detect in order: `video/mp4;codecs=avc1,mp4a.40.2`, `video/mp4`, `video/webm;codecs=vp9,opus`, `video/webm`. Test `start()` in try/catch, not only `isTypeSupported()`. [15, V2]
- **[medium]** Chrome WebM recordings have no duration and are not seekable (webm live format, crbug 642012). Fix by rebuilding Cues with a JS library, or play through a `SourceBuffer`. MP4 output avoids this. [10, V4]
- **[high]** `navigator.share({files})` needs transient activation (a tap) and the `web-share` Permissions Policy, else `NotAllowedError`. Test `navigator.canShare({files})` first. MDN lists both `video/mp4` and `video/webm` as usually shareable. `AbortError` on user cancel. HTTPS required. [11]
- **[high]** `captureStream(fps)` sets a maximum rate. Nothing is captured when the canvas does not repaint. Recording resolution equals canvas size. [14]
- **[low]** Chrome MediaRecorder records mono audio only (crbug 706013). [10]
- **[low]** `timeslice` in `start()` sets how much encoded data buffers before each `dataavailable`. [10]
- **Gap**: no source on whether WhatsApp, Viber, Telegram, or Messages accept WebM from the Android share sheet. Assume MP4 is required for reliable sharing.

### Voice effects

- **[high]** SoundTouchJS scoped packages (`@soundtouchjs/core`, `@soundtouchjs/audio-worklet`, `@soundtouchjs/formant-correction-worklet` 2.1.1) are MPL-2.0. The worklet exposes `pitch`, `pitchSemitones`, `playbackRate` AudioParams. The formant worklet does LPC formant preservation for natural voice shifts. The unscoped `soundtouchjs` npm package is still 0.3.0 LGPL-2.1. Use scoped packages only. Active monorepo, eleven packages. [17, V5]
- **[high]** Tone.js `PitchShift` is a delay-line shifter (sawtooth-modulated `DelayNode`), MIT, no AudioWorklet. `windowSize` trades latency against smoothness, 0.03 to 0.1 s recommended. Simplest option, lower quality on large intervals. [19, V6]
- **[medium]** Phaze: Unlicense, AudioWorklet phase vocoder, mono and multichannel. README dated January 2021, 42 commits, 11 open PRs. Not maintained. [18]
- **[high]** Rubber Band Library is GPL or paid commercial. Skip. [23]
- **[medium]** `@audio/shift`: MIT, 15 algorithms including cepstral formant-preserving mode. Only STFT-family algorithms stream incrementally. No AudioWorklet wrapper shipped. Would need custom worklet. [24]
- **[medium]** Preset recipes from a published voice changer: telephone = highpass 300 Hz + lowpass 3400 Hz + bitcrush, chipmunk = +12 semitones + lowpass 8 kHz, robot = ring modulator. That guide renders offline with `Tone.Offline`, the node chains transfer to live use. [20]
- **[low]** Desktop Chrome mic-to-speaker AudioWorklet latency: 78 to 152 ms default, 19 to 41 ms with `latencyHint: 0` and `echoCancellation`, `noiseSuppression`, `autoGainControl` all false. Measured 2020 on macOS. Not constant across a session. No Android data. [21]
- **Gaps**: Android AudioWorklet latency, `bungee-pitch-shift` (WASM newcomer, license unknown, npm page blocked), vocoder implementation, A/V sync through `MediaStreamDestination`, speaker feedback when monitoring with echo cancellation off. None of the four JS libraries states a SharedArrayBuffer requirement.

### PWA, GitHub Pages, dev loop

- **[high]** Project site at `https://<user>.github.io/<repo>/` needs Vite `base: '/<repo>/'`. Pages source must be GitHub Actions. Official workflow: permissions `contents: read`, `pages: write`, `id-token: write`, actions `configure-pages@v6`, `upload-pages-artifact@v5` (path `./dist`), `deploy-pages@v5`, concurrency group `pages`. [28]
- **[high]** vite-plugin-pwa precaches only `**/*.{js,css,html}` by default. Add `.wasm`, `.task` via `workbox.globPatterns`. Workbox `maximumFileSizeToCacheInBytes` defaults to 2 MiB (2097152). Since v0.20.2 the build throws (not warns) when an asset exceeds it. Raise it or exclude the big files from precache and cache them at runtime. Precache downloads only on first install or when the manifest changes. [25, 26, V11, V12]
- **[high]** Chrome install criteria: HTTPS, manifest with `name` or `short_name`, 192 px and 512 px icons, `start_url`, `display` standalone/fullscreen/minimal-ui, `prefer_related_applications` false or absent. Service worker fetch handler not required since Chrome 108 mobile and 112 desktop. `beforeinstallprompt` needs 30 s viewing and one tap. Screenshots and description recommended for richer install UI. [30, V15]
- **[high]** GitHub Pages limits: 1 GB published site, 10 min deploy timeout, 100 GB/month soft bandwidth, 10 builds/hour soft (not for custom Actions workflows), HTTP 429 on rate limit. No per-file limit stated on the Pages page. [27]
- **[medium]** Phone dev loop: Chrome DevTools `chrome://inspect/#devices` port forwarding, or `adb reverse tcp:5173 tcp:5173`, makes the phone open `http://localhost:5173`. `localhost` is a potentially trustworthy origin by hostname, so `getUserMedia` should work without HTTPS. Inferred from spec and docs, not device-tested. [29, V-notes]
- **[high]** Vite `server.host: true` or `--host` listens on LAN. `server.https` needs a certificate. `@vitejs/plugin-basic-ssl` makes a self-signed one, Vite recommends own certs. `allowedHosts` skips the check under HTTPS. LAN path needs HTTPS for `getUserMedia`. `adb reverse` path avoids this. [31]
- **[medium]** vite-plugin-pwa v1.2.0 current. v0.21.0+ uses Workbox 7.3.0. `@vite-pwa/create-pwa` v1.0.0+ targets Vite 7. Vite docs show 8.3.1. [26, 28]
- **Gaps**: camera and mic permission persistence in an installed Android PWA, autoUpdate vs prompt tradeoff, Pages preview environments (single `github-pages` environment, options are a `/dev/` subfolder or a second repo).

### Storage and privacy

- **[high]** Chrome and Edge: one origin can store up to 60% of total disk. Browser total capped at 80%. `navigator.storage.estimate()` in Chrome always reports 60% of total disk, not free space. `navigator.storage.persist()` is granted or denied silently from site engagement, no prompt. Persistent origins skip LRU eviction. Writes past quota throw `QuotaExceededError`. Quota is per origin, so every project under `<user>.github.io` shares one quota, one persist state, and one "clear site data". [33, 35, V13]
- **[high]** Chrome guidance: OPFS for file content, IndexedDB for other data, Cache Storage for app assets. OPFS is origin-private, invisible in the file manager, same quota as IndexedDB, deleted on clear site data. Sync access handles are worker-only, main thread uses `createWritable()`. `(await navigator.storage.getDirectory()).remove({recursive: true})` clears all. [34, 35]
- **[medium]** Multi-MB blobs in IndexedDB pass through structured clone (a copy on write and read). Hybrid pattern: OPFS files + IndexedDB metadata. Local storage is not backup, export path needed. [39]
- **[high]** CSP delivered by `<meta http-equiv>` works for a static SPA. Report-only mode cannot be set in meta. `frame-ancestors` and `sandbox` are ignored in meta (not fetched, general CSP knowledge). Per-directive needs for MediaPipe wasm (`'wasm-unsafe-eval'` in `script-src`, `blob:` in `media-src` and `worker-src`) not verified. [38]
- **[high]** coi-serviceworker injects COOP and COEP through a service worker. Browsers honor it. It reloads the page on first visit, must be a separate same-origin file (not bundled, not CDN). It registers at site scope, so it conflicts with the vite-plugin-pwa service worker (one SW per scope, inferred). Only needed for SharedArrayBuffer (wasm threads, multithreaded ffmpeg.wasm). With native MediaRecorder MP4 there is no need for ffmpeg, so skip it. [36, 37, V14]
- **[medium]** MediaPipe docs load wasm from jsDelivr `@latest` by default. A local build must pass a same-origin path. Docs say download the model into the project. The docs do not say that no network calls happen after load, and the verifier found they do in 1.0.x (see blocker above). [2, 40, V10]
- **Gaps**: gallery thumbnails (seek video to canvas), object URL lifecycle, export via `<a download>` in installed PWA, `showSaveFilePicker` on Android, camera and mic permission UX for kids, COPPA expectations for a hobby app (discovery found no kid-app sources).

## Contradictions / open questions

- MP4 encoder availability: the vendor guide [15] says Chromium writes MP4 only with an OS encoder. Stack Overflow [V2] says branded Chrome ships its own H.264. blink-dev [V3] says Android has no software H.264 encoder. Likely resolution: desktop Chrome always has H.264, Android relies on the hardware encoder (present on nearly all phones). Runtime feature-detect settles it.
- Triangulation: tfjs `triangulation.js` has 880 triangles [V7]. `canonical_face_model.obj` has 898 faces with separate UV indices [V8]. Use the tfjs index for geometry and remap OBJ UVs once at build time.
- Quota: a studio blog [39] says quota scales with available disk. MDN [33] and web.dev [35] say 60% of total disk. Official docs win.
- MediaPipe worker example: angle report said Google publishes one. Verifier found the docs code runs on the main thread. Build the worker in-house.
- Unanswered: mid-range Android fps for landmarker + WebGL warp at 720p. Android AudioWorklet round-trip latency. Face-only wasm + `.task` size. WebGPU delegate status for tasks-vision in 2026. Exact CSP directives that MediaPipe wasm needs. Whether Android messengers accept WebM from the share sheet. Camera and mic permission persistence in an installed PWA.

## Refuted claims

- "The telemetry behavior of `@mediapipe/tasks-vision` under fully same-origin assets is undocumented" (issue 6306, angle face). Verifier: the 1.0.1 README carries a Privacy Notice dated 2026-06-05 stating that MediaPipe Tasks APIs send metrics to Google. `vision_bundle.mjs` starts a logger on task creation that POSTs to `https://odml.pa.googleapis.com/v1/log` every 60 s. A maintainer comment (2026-06-10) said telemetry was being added with no opt-out planned. 0.10.35 lacks the endpoint. The "no LICENSE in tarball" part holds (14 files, no LICENSE or NOTICE, package.json declares Apache-2.0). The "model terms unstated" part is weakened: the Face Mesh V2 model card lists Apache 2.0 (card not fetched).
