# Research: filter techniques and idea catalog for facemaker

Date: 2026-09-26. Method: /deepresearch, 5 angle agents + 1 claim verifier. Scope: browser-side implementation with WebGL/Three.js and MediaPipe tasks-vision, local-only, Android Chrome + desktop. Companion: `01-tech-stack-2026-09-26.md`.

## TL;DR

All requested filter families are feasible on the chosen stack. Face warps and funny geometry: radial inverse-lookup warps in a fragment shader, handles composed in sequence, landmarks smoothed with a One Euro filter. Makeup: landmark polygon masks (lips, eyes) drawn to a small mask texture, blush as analytic blobs, skin smoothing as frequency separation. Backgrounds: MediaPipe ImageSegmenter selfie model (256x256 float16, about 35 ms on Pixel 6), mask feathered and temporally smoothed in shader, person composited over a looping video or procedural shader. Avatar: three-vrm v3 (MIT) driven by MediaPipe blendshapes (eyeBlink to blink, jawOpen to aa, mouthSmile to happy) and the transformation matrix slerped onto the head bone. Costumes: PoseLandmarker 33 points with `outputSegmentationMasks`, or one HolisticLandmarker call for face + pose + hands + mask. Sprites anchored to shoulder/hip quads. Extra idea sources: Snap Lens Studio categories, seven canned hand gestures, blendshape triggers, two-face lenses, mini-games.

## Key findings

### Face warp and funny geometry

- **[high]** Two warp families exist. (a) Fragment-shader radial warps: each handle is a centre, radius, and displacement or scale, evaluated as a backward map (inverse lookup) with a falloff flat at centre and rim, handles composed by running the sample coordinate through each in turn. Covers big eyes, big mouth, big head, small face, jaw slim, bulge, pinch. (b) Mesh warps: 468-vertex BufferGeometry with the video as texture, UVs from undeformed landmarks, positions from scaled landmarks. Verifier read the shader source of both ctbot000 repos and confirmed the inverse-lookup loop with early exit at `dd >= rr`. [W1, W2, F4, V1]
- **[medium]** Falloff functions in use: `(1 - (d/r)^2)^2` for pull handles, smoothstep `1 - t^2(3 - 2t)` for zoom handles. Both are flat at the rim so the warp cannot fold. The textbook Gustafsson falloff folds the image at small displacements. [W1, W2, V1]
- **[high]** Raw landmarks jitter by a pixel or two on a still face. Smooth with a One Euro filter before any geometric warp reads them. Suggested start: `min_cutoff = 1.0 Hz`, `beta = 0.007`. [W1, P8]
- **[high]** `FaceLandmarker` exposes `FACE_LANDMARKS_LIPS`, `LEFT_EYE`, `RIGHT_EYE`, `LEFT_EYEBROW`, `RIGHT_EYEBROW`, `LEFT_IRIS`, `RIGHT_IRIS`, `FACE_OVAL`, `CONTOURS`, `TESSELATION` as `Connection[]` (edge pairs `{start, end}`). They are for drawing, not ordered polygons. To fill a region, chain the edges into a ring. A wrong ring fills as a star. [W3, V2]
- **[high]** Triangle index for the mesh route: tfjs-models `triangulation.js` (880 triangles, Apache 2.0). `TESSELATION` is edges, not triangles, and cannot serve as an index buffer. [W4, F4]
- **[medium]** Parametric sliders per region (operator request) map directly onto family (a): one handle per region (nose, mouth, each eye, forehead, chin, ears via face-oval points), slider sets scale or displacement, a "wobble" mode animates displacement with a sine, "swirl" adds a rotation term inside the radius. Design inference, no source implements exactly this.
- **[low]** jeelizFaceFilter (Apache 2.0) outputs only detection, position, scale, rotation, and mouth opening. No dense landmarks. Not useful here. [W6]

### Makeup and beauty

- **[medium]** Region masks: repaint a 320 px 2D canvas each frame from landmark polygons and upload as one RGBA mask texture (R skin, G lips, B eyes and inner mouth). Lipstick = colour blend inside G. Blush and under-eye lift = analytic radial blobs in the shader, not polygons. Eyeliner = stroke along the eye ring, no source implements it. [W1]
- **[medium]** Skin smoothing = frequency separation, not plain blur. Split the frame into a low-frequency base and detail, suppress only small-magnitude detail (pores, blemishes), keep edges. The -auto repo uses three bands at six GPU passes per frame. Verifier confirmed the band split in shader source (`blotch = mid - low`, `pore = src - mid`). Both repos are one author, 0 stars, created 2026-09-20. Technique is standard, the specific code is untested by others. [W1, W2, V3]
- **[low]** CPU alternative for makeup (OpenCV.js `fillPoly` + `GaussianBlur` + `addWeighted`) exists but is not real-time on mobile. [W5]

### Animated backgrounds (segmentation)

- **[high]** ImageSegmenter selfie model: background index 0, person index 1. Variants: square 256x256 float16, landscape 144x256 float16. Multiclass model (256x256 float32): background, hair, body-skin, face-skin, clothes, others. [S1, V5]
- **[high]** Pixel 6 whole-pipeline latency: SelfieSegmenter square 33.46 ms CPU / 35.15 ms GPU, landscape 34.19 / 33.55 ms, multiclass 217.76 ms CPU / 71.24 ms GPU. Multiclass is too slow for live use on mid-range Android. [S1, V6]
- **[high]** GPU delegate needs its own canvas. The task creates a WebGL context on it and throws if a different context type exists. `MPMask.getAsWebGLTexture()` is bound to that task canvas. `getAsFloat32Array()` is an expensive GPU-to-CPU readback. Masks from `segmentForVideo` live only inside the callback, `clone()` to keep, `close()` to free. Confirmed in 1.0.1 typings. [S8, V7]
- **[medium]** Three.js integration options (inference): share the task canvas and context with the Three.js renderer, or read the mask back and upload as a DataTexture each frame. The shared-context path needs a test. [S8]
- **[medium]** Edge quality: naive upsampled 256 px mask gives a 3 to 4 px halo. Fix: blur (sigma 2) then steep sigmoid remap `1 / (1 + exp(-12 * (mask - 0.5)))`. Temporal smoothing over the last 3 masks removes hair flicker, more than 5 adds lag. Joint bilateral filter and light wrapping are the Meet-style upgrades. [S5, S6]
- **[medium]** Reported fps on a Pixel 3 (2018) in Chrome with WASM SIMD + WebGL2: ML Kit 256x256 model 19 fps, Meet 256x144 31 fps, Meet 160x96 60 fps. Unverified figures from the Volcomix README. [S5, V9]
- **[medium]** Known issue 6352 (open, 2026-08-31): tasks-vision 1.0.1 + GPU delegate + continuous `segmentForVideo` leaks Emscripten GL handles at about 1.2 MB/min. Reporter recreates the segmenter every 5 minutes. CPU delegate does not leak but halves fps. Single report, macOS. Monitor. [S3, V8]
- **[low]** One 2023 report says background quality got worse after migrating from legacy `@mediapipe/selfie_segmentation` to tasks-vision. Legacy solution superseded 2023-04-04. [S4, S7]
- **[high]** `PoseLandmarker` with `outputSegmentationMasks: true` returns a person mask from the same task. For costume features that already run pose, this removes the separate ImageSegmenter. [P1, V14]
- **Gap**: no source on animated background sources (looping video texture, caustics shader, parallax). Standard Three.js `VideoTexture` on a background plane and a fragment-shader caustic are the expected route. No fps figure for face + segmenter together on mid-range Android.

### 3D avatar (VTuber style)

- **[high]** three-vrm (pixiv) is MIT. Current major v3, npm latest 3.5.5 (2026-07-09). README pins `three@0.180.0`. v3 supports WebGPURenderer through `MToonNodeMaterial` (needs Three.js r167+). Loads VRM via a GLTFLoader plugin. [A1, V10]
- **[high]** VRM expression presets: aa, ih, ou, ee, oh, blink, happy, angry, sad, relaxed, surprised, lookUp, lookDown, lookLeft, lookRight, blinkLeft, blinkRight, neutral. VRM blink value 1 = closed. ARKit and MediaPipe `eyeBlinkLeft/Right` are also closedness, so no inversion. Caveat from issue 6368: MediaPipe docs do not define which side "Left" is, so selfie mirroring can swap eyes. Test on device. [A2, V11]
- **[medium]** Minimal mapping (design, derived from sources): `eyeBlinkLeft/Right` averaged to `blink` (per-eye winks only when one eye is clearly closed and the other open), `jawOpen` to `aa`, `mouthSmileLeft/Right` to `happy`, `browInnerUp` to `surprised`. Head pose: decompose the facial transformation matrix to a quaternion, slerp the head bone toward it with a damping factor (about 0.3 per frame). Lerp expression values (0.5) to cut jitter. [A3, A7]
- **[medium]** VRoid Studio exports do not carry the 52 ARKit blendshapes. Mapping 52 to the VRM preset set is lossy but sufficient for blink, mouth, smile. Repos with ARKit-blendshape VRoid characters exist (hinzka/52blendshapes-for-VRoid-face). [A3]
- **[high]** Kalidokit is deprecated (MIT, last publish about 4 years ago). It solved from landmarks. tasks-vision blendshapes plus the transformation matrix replace it. [A4, V12]
- **[medium]** Free models: Open Source Avatars registry, "100Avatars Series" by Polygonal Mind is CC0. Other collections vary (some CC-BY). Curate by hand: CC0 does not mean kid-appropriate. Ready Player Me demo (MIT) shows blendshape-driven avatars with Three.js. [A5, A6, V13]
- **Gaps**: VRM file size and Android load time, MToon performance on mobile GPUs, VRoid Hub license flags.

### Body overlays and costumes

- **[high]** PoseLandmarker web: 33 normalized landmarks + 33 world landmarks, visibility and presence per point. Anchors: shoulders 11/12, elbows 13/14, wrists 15/16, hips 23/24, knees 25/26, ankles 27/28. Lite, Full, Heavy bundles, all float16, same input shapes (224 detector, 256 landmarker). `detectForVideo` blocks the main thread, use a worker. [P1, P2]
- **[high]** HolisticLandmarker is in tasks-vision 1.0.1: one float16 bundle, 478 face + 33 pose + 2x21 hands = 553 landmarks, options `outputPoseSegmentationMasks` and `outputFaceBlendshapes`. Web modes IMAGE and VIDEO only. Pose sets the face and hand regions of interest, so it is cheaper than three separate tasks, at the cost of coupling (pose loss drops hands). [P3, P4, P8, V14]
- **[medium]** Costume rigging (design from sources): torso sprite on a quad spanning shoulders and hips with a perspective or affine transform. Limb sprites scaled and rotated between joint pairs. Mermaid tail: mask legs with the pose segmentation mask, draw the tail sprite anchored at the hips. No browser source shows the math end to end. VirtuStyle (2D canvas shirt fit) is the closest example, license unclear. Softwear (MIT) is a heavier 3D try-on with ONNX and cloth physics. [P6, P7]
- **[low]** Blog figures without hardware: Lite 15 ms CPU / 5 ms GPU, Full 30 / 8 ms, Heavy 80+ / 15 to 20 ms. GPU delegate on web runs through WebGL. [P8]
- **Gaps**: fps of face + pose (+ mask) together on mid-range Android. Whether separate tasks share one wasm instance from one `FilesetResolver` (the official pattern passes the same `vision` object to each task). 2D skeletal animation formats for the browser (DragonBones, Spine is commercial, Lottie for overlays).

### Filter idea catalog

- **[high]** Snap Lens Studio categories (live gallery, 2026-09): face swap (image and video), "What X Are You?", quiz, voice changer, liquify 2D, head scale, face deformation, zoom, window cutout, bald, beard constructor, eye colour, hair colour, hand tracking, sparkles, sticker on face, text on head, tic tac toe, colouring page, 3D falling objects. Templates: Distort, Face Morph, Face Paint, Face Mesh, Head Mesh, Paper Head, Portrait Particles, Segmentation, Makeup, Hair Color, Countdown, Chain Physics, Face in Picture. [C1, C2, C7]
- **[high]** Triggers: Snap fires effects on Mouth Open, Brows Raised, touch, per face index, with a cooldown. TikTok Effect House has trigger nodes for face movement, two-face movement, face expression, hand gesture, head movement, touch, and a "stretch random face" response. All map to MediaPipe blendshapes (`jawOpen`, `browInnerUp`, `mouthPucker`, `eyeBlink*`). [C5, C6, C12, C13]
- **[high]** MediaPipe Gesture Recognizer canned gestures: None, Closed_Fist, Open_Palm, Pointing_Up, Thumb_Down, Thumb_Up, Victory, ILoveYou. Default one hand. Custom gestures via Model Maker. Snap's own hand template recognizes open, close, horns, index finger, victory, thumb. [C8, C10, C11, V15]
- **[medium]** 2026 trend list (low-reliability blog): mini-games (catch falling objects, dodge with face, speak a word), two-face lenses ("both smiling" triggers a celebration), Y2K look (cyan or magenta grade, pixelated frame, scanlines, blink-triggered message), try-on utility. [C14 to C17]
- **[high]** Meta retired Meta Spark and removed third-party effects on 2025-01-14. Instagram has no open creator catalog to mine. [C18, V15]
- **[high]** Snap now pushes generative lenses (AI Edits, Dreams Animated, FaceGen). These need servers or large models. Out of scope for local-only. [C3]

## Feasibility map (analysis, not a sourced claim)

Feasible now on the stack: face paint and stickers, head-attached objects (hats, ears, glasses), distort, liquify, head scale, big eyes, parametric morph sliders, mouth-open, brow-raise and blink triggers, seven hand gestures, particles on trigger, "What X Are You?" spinner, quiz picker, countdown, falling-object catch game, face-dodge game, two-face "both smiling" celebration, background replace or blur, hair recolour (multiclass model, slow), bald cap, beard, eye colour, Y2K and VHS scanlines, pixelate, kaleidoscope, mirror, colour LUT, window cutout, zoom, voice changer, volume-driven scale (AnalyserNode).

Borderline: face swap between two live faces as a landmark-mesh texture swap (texture UVs from face A on mesh B). Not identity transfer, but funny. Stylized "old" or "baby" via proportion warp plus overlay textures (wrinkles, big eyes). Not photoreal.

Defer (generative model needed): photoreal aging or baby, gender swap, 3D cartoon and anime style transfer, prompt-based edits (see the on-device AI research note in TODO.md).

## Contradictions / open questions

- Pose Heavy input size: blog [P8] says 512x512, official [P2] says 256x256 for all three. Trust official.
- Face landmark count: blog [P8] and an older ai.google.dev holistic page say 468 or 543 total. Current docs say 478 face, 553 total. The difference is the 10 iris points.
- Segmenter latency: official [S1] 33 to 35 ms whole pipeline on Pixel 6. Forasoft [S6] claims about 2 ms model-only on the same phone. Different scopes, [S6] gives no source. Plan with [S1].
- `delegate: "GPU"` on web means WebGL, not WebGPU. Forasoft's WebGPU claims are unsupported by the 1.0.1 typings.
- Falloff formula: the angle report attributed `(1 - (d/r)^2)^2` to both ctbot repos. Verifier: only -auto uses it, only for pull handles. Both repos use rim-flat falloffs.
- Unanswered: fps for face + segmenter, and face + pose, on mid-range Android. Whether tasks share one wasm instance. Three.js access to the segmenter's WebGL texture without readback. VRM load time on Android. Which "Left" MediaPipe means under selfie mirroring.
